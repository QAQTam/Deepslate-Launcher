Current handoff and the next UI optimization spec live in `docs/current/` (`HANDOFF.md`, `SPEC-ui-optimization.md`; the older `SPEC-ui-restructure.md` is superseded).

## Project Overview

**深板岩启动器（Deepslate Launcher）** is a minimal Minecraft Java Edition launcher written entirely in Rust: an iced GUI on top of a framework-free core. Scope: download / launch / profiles / settings, plus **Fabric loader installation and launch** (mods are discovered by Fabric itself). Visual identity: kraft-paper yellow × slate gray, light/dark themes (no purple, no green).

## Build Commands

```bash
cargo run -p gui-iced    # Run the launcher (binary: deepslate-iced)
cargo build              # Build the whole workspace
```

## Architecture

### Cargo Workspace

- **`core/`** (`deepslate-core`): framework-free business logic. No GUI dependencies; long-running tasks report progress via `tokio::sync::mpsc` channels carrying `CoreEvent` (defined in `core/src/events.rs`).
  - **`net.rs`**: shared HTTP client (UA/timeouts) with retries covering both request sending and response-body reads (Mojang/Fabric meta endpoints are flaky).
  - **`eula.rs`**: fetches the official EULA (`https://www.minecraft.net/en-us/eula`) with a dedicated HTTP/1.1 client and clean UA (Akamai resets HTTP/2 and stalls on UAs containing `+https://`), extracts `#main-content` via `scraper`, normalizes only whitespace, and caches raw HTML + text + SHA-1 under `<root>/legal/`. The acceptance marker is `<root>/eula.txt` in the same `eula=true` format as the server; `accept()` is atomic. GUI acceptance additionally records the displayed text SHA-1 in `<root>/legal/eula-accepted.json`, and `check_for_update()` runs at startup: a changed hash invalidates the old acceptance and forces a fresh scroll/checkbox flow. A network failure is reported as a warning, never treated as “unchanged”. Client launch, local server, world generation, and the CLI all gate on it.
  - **`config.rs`**: AppConfig load/save, game/saves/versions directory resolution. `config.json` lives beside the executable.
  - **`profiles.rs`**: User profiles (offline + Microsoft), deterministic offline UUIDs.
  - **`auth.rs`**: Microsoft OAuth 2.0 flow (login.live.com → Xbox Live → XSTS → Minecraft Services). Authorization happens in the system browser; the user pastes the callback URL back, then `login_with_code` runs the token chain.
  - **`download.rs`**: Downloads versions/libraries/assets from Mojang's CDN. `download_all` is the shared concurrent downloader (progress events, `.part` atomic writes, SHA1 verification, retries) and is reused by the Fabric installer. Handles legacy `assets/virtual/<index>` materialization.
  - **`fabric.rs`**: Fabric loader installation via `https://meta.fabricmc.net/v2` (per-game loader list, `profile/json`). Ensures the vanilla base version, downloads the profile's maven libraries (asm / sponge-mixin / intermediary / fabric-loader), writes `versions/fabric-loader-<loader>-<game>/<id>.json`, creates the instance `mods/` directory.
  - **`versions.rs`**: Disk scan of `versions/*/*.json` for the GUI's installed list; detects vanilla/Fabric/Quilt/Forge/NeoForge from id + mainClass and resolves whether a launchable jar exists through the inheritance chain.
  - **`nbt.rs`**: Generic gzip NBT reader/writer (preserves tag/list element types) used by save management; bounded list lengths/nesting to reject corrupt files.
  - **`saves.rs`**: World parsing from `level.dat` (name / game mode / difficulty / hardcore / cheats / last played / version / size / icon), rename (LevelName only), duplicate (new folder id, resets LastPlayed/session.lock), delete-to-`.deepslate-trash`, empty trash. World folder id is the `--quickPlaySingleplayer` argument.
  - **`maps.rs`**: Global map library. `maps/<uuid>/` is a standard world directory plus `map.json` (source, generator seed/type, DataVersion, last played). `instance/saves` is linked to `maps/`; import supports directory/zip (zip-slip/symlink/size guards), export writes a portable zip, duplicate/rename/trash operate on map ids. Per-map snapshots live in `<root>/backups/maps/<id>/` (keep 5) with atomic restore. `MapSummary` derefs to `WorldSummary`.
  - **`runtime.rs`**: Resolves `game/`, `instance/`, `maps/`, `cache/`, `backups/`; ensures `instance/saves -> maps` idempotently. On first run it imports legacy saves into the library and renames the old directory to `saves.legacy-<timestamp>` instead of deleting it. Handles old `saves_isolation` symlinks as well.
  - **`worldgen.rs`**: External world generation. Runs the vanilla server jar in `maps/.staging/worldgen-*` with `WorldSpec` (name/seed/type/gamemode/cheats), waits for `Done (`, stops, then adopts the generated `world/` into `maps/<uuid>/` with `map.json`. No Fabric mod/client API involved. Jobs write `.job.json` (PID, `kill_on_drop`) and `.complete.json`; startup `cleanup_stale` kills orphan servers, removes partial staging, and re-adopts completed-but-unadopted worlds. Generated worlds are validated via `saves::validate_world_dir` before and during adoption.
  - **`game_options.rs`**: Writes `options.txt` defaults (`lang:zh_cn`, `onboardAccessibility:false`, `skipMultiplayerWarning:true`, `tutorialStep:none`, `narrator:0`). First Deepslate takeover force-sets them and writes `.deepslate/game_defaults_v1`; later runs only fill missing keys so in-game choices win.
  - **`branding.rs`**: Copies the client jar's `version.json` into `<instance>/deepslate/branding/` with `name` suffixed by the launcher brand and prepends that directory to the classpath. Verified on vanilla 26.3 (`Minecraft 26.3 | Deepslate`); Fabric's Knot game classloader ignores extra classpath resources, so branding is vanilla-only for now.
  - **`server.rs`**: Local server management. Resolves `downloads.server` through `inheritsFrom`, downloads to `<root>/servers/<version>/server.jar`, writes EULA and `server.properties` (preserves user keys except port/online-mode), and streams logs as `CoreEvent::ServerLog` + `ServerState::Ready` on `Done (`. Vanilla runs `java -jar server.jar`; Fabric versions detect the profile's library list and run `FabricServerLauncher` with `-Dfabric.gameJarPath=<vanilla server jar>` (KnotServer, loads `mods/`). `create_world` remains the low-level generator (temporary dir, `level-type`, seed, gamemode, port 0, `Done (`, `stop`, `level.dat` validation, NBT metadata); it can write a `.deepslate-worldgen.json` PID marker for crash cleanup, and `worldgen::generate` wraps it and writes the result into the map library instead of a version saves dir.
  - **`mods.rs`**: Reads the instance `mods/` directory, parses `fabric.mod.json` (id/name/version/description/authors/environment) with filename fallback, toggles `.jar` ↔ `.jar.disabled`, and moves deletions to `mods/.deepslate-trash/`. No dependency resolution or downloads.
  - **`launch.rs`**: Version-chain loading/merging, argument construction, and process spawning. Version JSONs load local-disk-first (loader versions like Fabric only exist locally), official manifest as fallback, with chain loop detection; merging follows HMCL semantics (child wins scalars when present, libraries union child-first deduped by `group:artifact` keeping base/native variants distinct, `arguments` parent-first then child appended, legacy `minecraftArguments` replaced wholesale) — see `merge_version_json` tests. Mojang `rules` use last-match-wins semantics with OS/arch/feature evaluation (`rules_allow`); `arguments.game`/`arguments.jvm` are expanded with the full placeholder set (`${auth_*}`, `${classpath}`, `${natives_directory}`, `${launcher_*}`, `${user_type}` = `msa`/`legacy`, …). `LaunchOptions.quick_play` appends `--quickPlaySingleplayer/Multiplayer/Realms` (26.x), `branding` prepends the vanilla-only `version.json` overlay, and `apply_game_defaults` writes Chinese/no-onboarding `options.txt` defaults before spawn. Missing libraries/natives are downloaded concurrently, natives (`${arch}` 32/64) extracted, and the client jar resolved by walking the chain (`jar` field override first). `prepare()` returns a printable `LaunchPlan`; `launch()` spawns it. stdout/stderr are piped and forwarded line-by-line as `CoreEvent::GameLog`. `game_dir` holds shared files (versions/libraries/assets/natives); `instance_dir` is passed as `--gameDir`. The current product uses `root/game` for both and links its `saves` to the global map library; legacy per-version isolation is deprecated.
  - **`backup.rs`**: Legacy version-scoped save backup helpers, retained for old CLI/debug paths. The product path now uses the global map library; map export (`maps::export_zip`) is the portable backup format. Do not use `backup::restore` against a live `saves -> maps` symlink.

- **`gui-iced/`** (bin `deepslate-iced`): iced 0.14 frontend, consumes `core` directly. Progress events flow through a static broadcast bus (`gui-iced/src/main.rs`: `EVENT_BUS` + `core_event_sender()`) into an iced `Subscription`. Styling lives in `gui-iced/src/style.rs` (dual light/dark `Scheme`s selected by `dark_mode`, persisted in `config.ui_mode`). Page/card entrance animations use iced `Animation` + `Float` transforms (300ms page switch, 400ms boot), ticked by an 8ms `iced::time::every` subscription only while animating. The version pick_list reads a cached `filtered` list (recomputed by `refilter()` only when versions load or the tab changes) instead of cloning per frame — see the `switch_perf` tests in `main.rs` for the perf profile. Pages: Home (continue last map), Launch (startup hero, quick join, collapsed account/maintenance/advanced sections), Friends (read-only Minecraft friend snapshots), **World/Maps** (global map library; world actions behind a More menu), **Server**, **Mods**, Settings (appearance incl. log-window/branding/Chinese-defaults toggles, root dir, download concurrency, map-library info, save/reset). Optional game-log window: when `config.log_window` is on, launching the game spawns a separate `deepslate-iced --log-window` child process; the main process pipes `GameLog` lines into its stdin (`O\t`/`E\t` prefixed). The child renders them (stderr in red, newest on top, 2000-line auto-compacting buffer) and auto-closes a few seconds after stdin closes. EULA is deliberately **not** routed through this child: it is a blocking full-window modal in the main iced window (`stack` + `opaque`), with the pending launch/server/create-world action resumed after acceptance. Headless/debug flags: `--install-fabric <mc> [--loader <v>] [--root <dir>]`, `--print-command <version-id> [--java <home>]` (prints the resolved `LaunchPlan` without spawning), `--launch <version-id> --accept-eula [--root <dir>] [--java <home>] [--quick-save <world>|--quick-server <host:port>] [--disable-multiplayer] [--disable-chat] [--fullscreen] [--width N] [--height N] [--graphics-backend default|opengl|vulkan]` (launches headlessly, logs to stderr), `--list-saves <version-id>`, `--list-mods <version-id>`, `--host-server <version-id> --accept-eula [--port N] [--memory MB]`, `--create-world <version-id> --accept-eula [--name ...] [--seed ...] [--flat] [--cheats] [--gamemode ...]`, `--generate-map <version-id> --accept-eula ...`, `--list-maps`, `--import-map <zip|dir>`, `--export-map <map-id> [--out <zip>]`, `--trash-map <map-id>`, `--backup-map <map-id>`, `--list-map-backups <map-id>`, `--restore-map <map-id> [--backup <name>]`, `--launch <version-id> --accept-eula ... --quick-map <map-id>`, `--rename-save/--copy-save/--trash-save <id> --saves-version <version-id> [--new-name <name>]`.

Note: data paths still default to the historical `~/Games/ObsidianLauncher` and legacy `~/.config/obsidian-launcher` fallback so existing game files keep resolving.

### Directory Layout

Shared files live under `root_dir/game/` (`version_isolation=false`) or `root_dir/` (`version_isolation=true`): `versions/`, `libraries/`, `assets/`, `natives/`, `mods/`.

The **instance dir** (`--gameDir`) is `root_dir/game` for the current single-build layout. Its `saves` is a symlink/junction to `root_dir/maps/`; the map library is the source of truth and survives game reinstalls/updates. `root_dir/cache/` holds `server.jar` and worldgen staging; `root_dir/backups/` is reserved for map backups.

Legacy `version_isolation` / `saves_isolation` settings are deprecated. Old `saves/` contents are imported into `maps/` on first map-page open, then the old directory is kept as `saves.legacy-<timestamp>`; old `saves_isolation` symlinks are migrated the same way.

Fabric versions use the official layout `versions/fabric-loader-<loader>-<game>/fabric-loader-<loader>-<game>.json` with `inheritsFrom` pointing at the vanilla version; the client jar is resolved from the parent directory at launch.
