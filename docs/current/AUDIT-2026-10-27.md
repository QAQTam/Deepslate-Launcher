# 独立审计：功能、视觉、设计与安全

日期：2026-10-27。范围：当前工作区 Rust `core` 与 iced GUI；全程未调用子代理。

## 结论与证据边界

存在需要修复的缺陷，不建议把“编译通过、现有测试全绿”视为可发布依据。

- `cargo build --workspace --offline` 成功。
- `cargo test --workspace --offline`：core 70 通过、4 忽略；GUI 3 通过。
- 额外临时探针：8 个 core 行为断言、4 个 GUI 状态机断言失败，复现下列 12 项缺陷。失败是产品行为未满足断言，不是编译失败。
- GUI 状态机探针不执行返回的 `Task`，只验证是否错误放行、选错状态；没有实际删除地图。
- core 探针仅使用临时目录、仓库已有 `level.dat` fixture、假令牌和惰性标记数据。凭据/重置测试使用复制到临时目录的测试可执行文件，并隔离 HOME、XDG_CONFIG_HOME 和配置路径。没有读取或修改真实账号、地图。
- 使用 iced tiny-skia 离屏渲染，检查暗色启动页、设置页的 900×560 与 1040×700 两种尺寸。这不是桌面端到端鼠标/键盘测试。
- 未进行真实 Microsoft 登录、真实 Minecraft 客户端/服务端启动、联网忽略测试、Windows/macOS 实机验证或依赖漏洞数据库扫描。当前没有图形显示环境，且未安装 cargo-audit。
- 临时探针、测试 include、临时 dev-dependency 和对应 lockfile 条目已撤回。撤回后重新运行原有测试与构建成功。以下问题仍未修复。

分级：P1 = 优先修复的安全/数据完整性/关键路径问题；P2 = 明确的功能、可用性或防御性问题；P3 = 次要信息架构问题。不是 CVSS 评分；“源码确认”与“动态复现”分开标记。

## 一、已动态复现的 12 项行为缺陷

### A01 · P1 · 原生库 ZIP 路径穿越，可越界写文件

**证据：动态复现。** `core/src/launch.rs:1302-1329`。

`extract_natives` 只检查扩展名为 dll/so/dylib，直接把 ZIP 条目名 join 到目标目录，没有拒绝绝对路径、`..` 或验证落点。

探针通过公开的 `launch::prepare` 进入真实解压路径，预置 native jar 条目 `../../../outside.so`，成功把惰性标记写到临时根目录，而不是 `game/natives/audit/`。不涉及执行代码。

影响：攻击者能控制被解压的 native jar 时，可创建/覆盖当前用户可写的、符合扩展名过滤的目录外文件。不能据此宣称已证明无需前提的远程代码执行；前提是恶意/被替换的库或版本来源进入启动流程。

建议：使用安全相对路径解析（例如 enclosed_name），拒绝 parent/root/prefix 组件，检查目标目录 containment，并考虑符号链接、解压总量上限。

### A02 · P1 · 凭据明文落盘，未限制文件权限

**证据：动态复现。** `core/src/profiles.rs:8-19,68-75`。

`access_token` 和 `refresh_token` 直接 JSON 序列化后 `fs::write`，没有 keyring 或 owner-only 权限设置。隔离探针在当前环境得到 `profiles.json` 权限 **0664**。若父目录允许访问，其他本机用户可读取凭据，同组用户还可能修改它。

权限随 umask 和父目录权限变化，不应理解为所有系统必然是 0664。

建议：refresh token 使用系统凭据库；至少目录 0700、文件 0600，原子写入，并修正已有文件权限。不要只依赖 umask。

### A03 · P1 · 启动命令日志泄漏 Minecraft access token

**证据：动态复现。** `core/src/launch.rs:953-960,1171-1194,1386-1387`。

`LaunchPlan::command_line` 原样拼接游戏参数，实际启动时会 `println!` 输出。假令牌探针确认日志字符串包含完整 access token。

影响：终端记录、系统收集的 stdout 或用户提交的排障日志可能泄漏游戏会话令牌。这里证明的是 access token，不是 refresh token 也被打印。

建议：区分执行参数与日志展示参数，按已知令牌值及参数名脱敏，覆盖现代与 legacy 占位符路径。

### A04 · P2 · 已有非空文件完全跳过 SHA1，“校验/修复”名不副实

**证据：动态复现。** `core/src/download.rs:158-162,177-185`；`core/src/server.rs:197-209`。

预置内容为 `corrupt` 的非空文件，给出不匹配 SHA1，下载器返回 `Ok(0)`，不检查哈希。新下载内容会校验，但缓存文件不会。

影响：损坏的 jar/library/资源无法通过再次下载修复；“安装/校验服务端”也会把损坏的 server.jar 当成有效文件。

建议：有预期摘要时先校验已有文件；失败后重新下载。校验结果缓存需要与文件大小/mtime 等失效条件绑定。

### A05 · P1 · 含目录的地图导出后无法再导入

**证据：动态复现。** `core/src/maps.rs:715-718,784-801,821-827`。

导出器写入 `region/` 等显式目录条目。导入器却先调用 `validate_relative`，按 `/` 拆分后把尾部空段判为非法，之后才检查 `entry.is_dir()`。

使用有效 level.dat 与 region 子目录执行 import_dir → export_zip → import_zip，得到：

```text
Err("zip 中包含非法路径: region/")
```

现有 round-trip 测试只有根目录文件，未覆盖真实世界常见的目录结构（`core/src/maps.rs:874-911`）。

建议：目录路径规范化时允许单个尾部分隔符，仍拒绝中间空段、`.`、`..` 和绝对路径；增加真实层级结构 round-trip 测试。

### A06 · P1 · 游戏运行中仍允许删除、重命名、复制或导出 live 地图

**证据：删除放行已由状态机复现；其他操作为源码确认。** `gui-iced/src/main.rs:984-1035,1104-1129,3123-3193`；`core/src/maps.rs:24-27,309-338,370-387`。

世界页的 busy 状态只禁用“进入”。确认删除时没有 game_running/launching 检查，探针得到“正在移入回收站...”并返回操作 Task。重命名、复制、导出同样没有保护；备份和恢复反而有检查（`gui-iced/src/main.rs:1154-1177`）。

影响：Linux 下正在使用的世界目录可能被移动，游戏后续写入失败；复制或导出会得到不一致快照；修改 level.dat 可能与游戏保存互相覆盖。未对真实地图实施破坏性验证。

建议：所有地图操作统一到核心层锁/任务互斥；对游戏和生成任务检测占用，UI 同步禁用，不能只依赖按钮状态。

### A07 · P1 · “重置所有配置”保留当前凭据，可能误删旧档案

**证据：动态复现。** `core/src/config.rs:179-186`；`core/src/profiles.rs:40-52`。

`reset_all` 先删除 config.json，随后调用依赖该配置的 `profiles::path`。路径解析因此退回 legacy 配置目录，而不是原来的 `<root>/config/profiles.json`。

隔离探针结果：

```text
current_profiles_exists=true
unrelated_legacy_profiles_exists=false
```

影响：用户以为已清除账号，实际在线 token 仍保留；另一份 legacy 档案却可能被删除。

建议：删除前解析并固定所有目标路径，明确当前配置与 legacy 配置的清理范围；增加 v2/legacy 双存储隔离测试。

### A08 · P2 · 离线 UUID 算法与 Java Edition 的离线身份不兼容

**证据：动态对照复现。** `core/src/profiles.rs:77-91`。

当前实现仅对名字 MD5 并加连字符，缺少 `OfflinePlayer:` 前缀和 UUID v3/variant 位处理。

```text
Steve 当前结果：81b8a1b7-7068-d06e-1c81-90825253066f
Java 离线算法：5627dd98-e6be-3c21-b8a8-e92344183641
```

影响：同名身份与其他启动器/离线服务端不一致，迁移时可能出现不同玩家数据或归属。不能直接推导成“所有离线服务器都无法加入”。

建议：使用 Java nameUUIDFromBytes 兼容算法；给已有档案提供迁移，不能静默改 UUID 导致旧玩家数据不可达。

### A09 · P2 · 相对根目录产生坏 saves 链接，却返回成功

**证据：动态复现（Linux）。** `core/src/runtime.rs:38-46,71-74,190-203`；`gui-iced/src/main.rs:781-790`。

设置/CLI 没有把 root 规范化为绝对路径。用相对 root 调用 runtime::ensure，symlink 的目标保留相对 root；目标被相对于 `game/` 再次解释，实际链接不存在，ensure 仍返回成功。

建议：输入校验时转成绝对路径，或计算相对于链接父目录的正确目标；建立后验证可解析。绝对 root 的现有测试没有覆盖此分支。

### A10 · P2 · 保存的默认档案在重启加载时被忽略

**证据：动态状态机复现。** `gui-iced/src/main.rs:569-576,607-609,796-803`。

保存设置写 config.last_profile；加载却只使用 ProfileStore.last_used。ProfileSelected 也没有更新 store.last_used。探针中配置 player1、store 为 player0，最终选择 player0。

建议：统一唯一的“上次档案”来源，并测试保存→重启还原。

### A11 · P2 · 切换根目录后保留旧版本/地图/档案缓存

**证据：旧已安装版本仍可选择已动态复现；其他缓存未清理为源码确认。** `gui-iced/src/main.rs:781-790`。

RootDirChanged 只改配置和 EULA 状态，不重扫 local_versions/local_choices、不清理 saves/mods/profiles，也不关联旧异步响应的 root。

影响：界面显示 A 根的数据，动作却使用 B 根路径；可出现错误的“已安装”、启动失败、错误刷新目标。当前探针没有实际执行跨 root 删除。

建议：采用 root generation/request id，变更时禁用活动任务或提示重启，重载所有依赖 root 的状态；异步返回需要核对来源。

### A12 · P2 · 任意下载 100% 事件都会解除当前游戏下载锁

**证据：动态状态机复现。** `gui-iced/src/main.rs:1599-1605`；`core/src/download.rs:226-239`。

DownloadProgress 没有任务身份。当前客户端下载中，收到模拟服务端 100% 事件后 downloading 立即变 false，而不是等当前任务 DownloadFinished。客户端资源与服务端/生成任务可以从不同页面发起。

影响：可能提前允许第二个任务或启动；同一目标的下载还共用固定 `.part` 路径（`core/src/download.rs:288-303`）。探针证明的是锁错误解除，未宣称已复现最终文件竞争损坏。

建议：事件带 operation id；进度不是完成状态，锁由对应任务的终态释放。

## 二、源码确认但未做真实服务端/账号或破坏性验证的风险

### B01 · P1 · 在线 token 没有过期检测/刷新路径

`core/src/auth.rs:144-155` 记录有效期，`core/src/profiles.rs:15-19,124-146` 持久化 refresh_token/expires_at；`gui-iced/src/main.rs:1906-1912,1944-1952` 启动时直接使用已存 access_token。全项目相关引用仅存取这些字段，没有 refresh_token grant 或刷新链。

结果：令牌过期后仍然启动为在线身份，直到 Minecraft 服务拒绝会话；用户只能重新走浏览器登录。尚未使用真实账号等待过期实测。

建议：启动前刷新 MS→Xbox→XSTS→Minecraft 凭据，更新有效期并原子持久化；区分网络故障、撤销授权和可离线启动。

### B02 · P2 · NBT gzip 与模组元数据解压没有总量上限

`core/src/nbt.rs:137-145` 对 gzip 无界 read_to_end，单个标签的长度/深度保护发生在完整解压后；`core/src/mods.rs:157-163` 无界读取 fabric.mod.json。

结果：恶意或异常本地内容可以造成内存耗尽。地图 ZIP 的 16GiB 上限限制的是外层条目，不是内层 gzip 解压后的 NBT。未运行内存耗尽攻击。

建议：对解压后的总字节、整体标签数、预分配和元数据长度设预算，使用限长流式读取。

### B03 · P2 · OAuth 回调缺少请求绑定和 PKCE 防护

`core/src/auth.rs:164-177,306-319`；`gui-iced/src/main.rs:2220-2231`。

授权 URL 没有 state/code_challenge，换码没有 code_verifier；GUI 只查找输入中的 code=，不校验回调来源/本次请求。手动粘贴场景仍应防止被诱导粘贴他人回调导致账号替换；这里没有证明能直接窃取任意账号。

建议：使用自有应用身份和符合提供方要求的授权流程、随机 state/PKCE；通过 URL parser 校验回调并解码参数，使用表单序列化而不是拼接裸授权码。

### B04 · P2 · “本地服务端”默认关闭正版验证，未强制限制监听接口

`core/src/config.rs:131-134` 默认 online-mode=false；`core/src/server.rs:223-236` 没有设置 loopback server-ip。GUI 虽有警告，但“本地”不是网络隔离保证（`gui-iced/src/main.rs:3692-3699`）。

若服务端按自身默认监听所有接口，局域网或已做公网端口映射的机器可能暴露无认证服务。实际监听地址本轮未启动 server.jar 测量。

建议：默认 loopback + 正版验证；若明确选择局域网/离线模式，单独确认风险并展示真实监听地址。

### B05 · P2 · 陈旧生成任务清理只凭 PID，会终止仍在进行的生成或 PID 复用的进程

`core/src/worldgen.rs:183-196,258-290`；`core/src/server.rs:523-537,540-590`。

清理 staging 时遇活 PID 会跳过，但随后遍历 server cache，cleanup_generation_dir 又会终止活 PID；没有检查 marker 的 cwd、进程启动时间、所属 launcher 或工作锁。因此两个启动器实例/同时生成时可能互相打断，PID 复用还可能误伤其他同用户进程。

未执行跨实例杀进程测试，以避免破坏。建议使用全局任务锁和进程身份验证，明确 orphan 的判断，不能把“PID 存在”当“应该杀”。

## 三、视觉缺陷

### C01 · P1 · 允许的最小窗口导致关键控件消失或压扁

**证据：tiny-skia 离屏渲染。**

- 900×560：启动页底部“档案”卡只剩标题和被压成细线的输入，Microsoft 登录流程不可见；“快速加入服务器”卡只剩标题；Java 重新扫描不可见。
- 900×560：设置页“保存设置”“重置所有配置”均不可见，页面不能滚动。
- 1040×700：这些控件恢复可见，说明是高度约束/布局分配问题，而不是未实现。

源头：`gui-iced/src/main.rs:2324-2328,2869-2898,3969-3999` 明确不使用整页滚动，而 `gui-iced/src/main.rs:4785-4789` 允许 900×560。

离屏渲染图片（临时文件，不是实际桌面截图）：

```text
/tmp/deepslate-audit-Launch-900x560.png
/tmp/deepslate-audit-Settings-900x560.png
/tmp/deepslate-audit-Launch-1040x700.png
/tmp/deepslate-audit-Settings-1040x700.png
```

建议：页面增加垂直滚动、首屏优先主操作，避免非滚动 column 在有限空间把交互项压到零高度；需要测实际 layout/render，而不是只调用 view。

### C02 · P2 · 小字和主按钮对比度不足

**证据：根据源码 RGB 计算 sRGB 相对亮度对比度。** `gui-iced/src/style.rs:27-57,157-166`。

| 组合 | 对比度 |
| --- | ---: |
| 暗色主按钮白字 / #d2a24c | 2.33:1 |
| 暗色主按钮 hover 白字 / #e4bb6e | 1.81:1 |
| 亮色主按钮白字 / #a9772b | 3.92:1 |
| 暗色辅助文字 / 卡片 | 2.78:1 |
| 亮色辅助文字 / 卡片 | 2.55:1 |
| 亮色 placeholder / 输入框 | 2.69:1 |

对普通小字号文本，以 WCAG AA 的 4.5:1 作为可读性基准，上述组合均不足。辅助文字大量使用 9–11px（如 `gui-iced/src/main.rs:2297,2425,2773,3225-3227`），进一步降低可读性。不是所有正文都不合格：muted/card 的计算结果暗色 5.27、亮色 4.86。

建议：黄底按钮使用深色文字；提高 faint 和 placeholder 对比度；关键信息不要依赖低对比度 10px 小字。

## 四、交互与产品设计问题

### D01 · P2 · EULA 模态没有拒绝/取消出口

`gui-iced/src/main.rs:2335-2336,2393-2455`：遮罩阻断主界面，操作只有重试、勾选、同意；不存在取消本次启动或不同意返回的动作。

结果：用户想拒绝协议、或首次获取失败想先管理地图，只能关闭整个应用。授权应阻断游戏相关动作，而不应强迫同意才能返回启动器。

建议：增加“不同意/取消”，清空 pending_action，返回启动器且不启动游戏；协议更新也应允许退出该动作。

### D02 · P2 · 首次接管实例强制关闭旁白，文案却说“只补缺失项”

`core/src/game_options.rs:20-28,56-61,84-94` 在首次接管时强制覆盖 lang、narrator 等已有值；`gui-iced/src/main.rs:3902-3905` 对用户仍宣称只补缺失项。

结果：已有实例的语言、教程、辅助功能选择被覆盖，旁白用户可能失去可访问性；这不只是美观问题。

建议：默认尊重现有值，语言预设与辅助功能分离；强制应用必须显式确认。

### D03 · P2 · 多版本共用 live 地图和 mods，却没有兼容性护栏

`core/src/runtime.rs:38-49` 使用同一实例和地图目录，`core/src/mods.rs:58-60` 在当前默认配置下也共享 mods。`gui-iced/src/main.rs:956-961,1898-1986` “进入世界”使用全局选中的版本，没有世界版本比较、升级/降级警告或自动备份。

结果：用户从“已安装”切换原版/Fabric/不同 MC 版本时，会复用同一批 mod 和地图；不兼容 mod 可能阻止启动，错误版本开图可能破坏数据。Minecraft 自身可能提示，但启动器一键进入不应假设下游永远兜底。

建议：世界与启动配置关联；跨版本进入前提示并快照；mods 按兼容实例管理，即使地图仍保持全局。

### D04 · P2 · 回收站清空为单击永久删除，无二次确认

`gui-iced/src/main.rs:1211-1216,1565-1576,3410-3413`；`core/src/maps.rs:392-408`。

普通删图有二次点击且移回收站，真正不可逆的清空却直接执行，保护强度倒置。
